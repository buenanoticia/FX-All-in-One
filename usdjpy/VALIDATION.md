# VALIDATION — USDJPY v1.1.1

作成日：2026年10月26日  
対象：`FX_AllInOne_USDJPY_v1_1_1.pine`

## 報告された問題と今回の確認範囲

利用者提供画像では、v1.1.0が過去参照300本・履歴上限299本の実行時エラーを出し、131行目のS/R用 `line.new()` で停止しています。保存済みv1.1.0ソースの同じ行と一致しました。

今回のv1.1.1は、公式資料に基づいて `max_bars_back(time, 5000)` を追加した修正版です。**作成側ではTradingViewのコンパイラー・Pine実行エンジンへ接続していないため、v1.1.1のコンパイル成功・ライブ動作確認済みとはしていません。**

v1.1.0については、以前の利用者画像で5分足の描画が確認されていますが、今回のライブ時エラーも確認されています。以前の静的テスト通過は、ライブ動作の保証になっていませんでした。

| 履歴確保の配置 | ソースを確認 | `time` の5000本指定がグローバルに1回だけあり、条件分岐・描画より前 |

| 境界とピボット経過 | Pythonの保持範囲モデル | 50・299・300・301・1000・4900の境界、1本進行時の削除を確認 |

テストの生出力は `tests/test_output.txt` に収録しています。

**Python参照モデルはPineの履歴自動推定、実際の時刻変換、メモリ管理、ライブ更新、描画エンジンを実装していません。** 68件という数は、チャートでの動作成功、アラート配信、収益性を保証するものではありません。

S/Rの保持条件は `b >= bar_index - srLookback` です。その最小値を線の起点に使うため、起点の過去方向の距離は最大 `srLookback`、設定上限では4900です。これを5000の時刻履歴でカバーします。5000はS/R探索期間の変更ではありません。

## TradingViewでの優先確認

| 操作 | 確認する内容 |
|---|---|
| 旧版を保存し、新版の全文を貼り付ける | `//@version=6` と `indicator()` を二重にしない。コンパイル結果を確認 |
| FOREXCOM:USDJPY・通常5分足へ追加 | 短縮名 `UJ 1.1.1`、MA・S/R・パネルが表示され、赤いエラーが消える |
| 使用する設定を再確認 | 特に探索期間300、幅モード、ATR設定、3,000通貨の参考数量 |
| 市場営業中に次の足まで確認 | 新しい足と価格更新に応じて描画が継続し、履歴エラーが再発しない |
| S/R探索期間300の境界 | 300本前の候補が残る場面でも停止しない。条件を満たさなければ線が0本なのはあり得る |
| 探索期間50・4900の比較 | それぞれでも履歴エラーがないかを実機で確認。負荷・必要履歴は別途確認 |
| 1分・15分・1時間へ切り替え | ATRの上位・下位取得と描画が継続する |
| 過去位置ラベルOFF/ON | 表示位置が変わるだけで時刻バッファエラーが起きない |
| 固定幅20 / 25、3,000通貨 | 600円 / 750円の参考換算。実注文は変更しない |
| 新版でアラートを再作成 | 使用する設定と時間足で「バーの終値ごとに1回」。チャート変更だけで旧アラートを更新した扱いにしない |

実行時エラーで停止したインジケーターの表示を、新しい相場判断の根拠として使わないでください。ブローカーの実ストップはこのスクリプトから管理されません。注文の受付状況は注文画面で別途確認します。
